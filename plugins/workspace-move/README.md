# 작업공간 대화 옮기기

DSH 왼쪽 목록의 대화를 **다른 작업공간으로 옮기는** 플러그인이에요. 제목과 대화 기록, 세션 id를 그대로 가져가고, 옮긴 뒤에는 대상 작업공간 폴더에서 이어서 작업해요.

DeepSeek 공식 플러그인이 아니에요. DSH에 아직 공식 "대화 이동" 기능이 없어서, 플러그인이 세션 로그의 헤더 `cwd`와 작업공간 소유 기록을 함께 맞추는 방식으로 옮겨요.

## 쓰는 법

1. 사이드바에서 옮길 대화의 **…** 메뉴를 엽니다.
2. **작업공간 이동**을 고릅니다.
3. 옮길 작업공간을 고르고 **옮기기**를 누릅니다.
4. "○○ 작업공간에 옮겼어요"가 나오면 끝이에요. 사이드바에서 원래 작업공간에서는 사라지고, 대상 작업공간 맨 위에 나타납니다.
5. 잘못 옮겼으면 결과 화면의 **되돌리기**를 누릅니다.

옮긴 대화를 열면 기록과 제목이 그대로이고, 다음 요청부터 대상 작업공간 폴더에서 실행돼요.

**지금 보고 있는 대화**는 그 자리에서 바로 옮길 수 없어요. DSH가 앱이 켜져 있는 동안 그 대화의 기록 파일을 계속 잡고 있기 때문이에요. 확인 창에서 **다시 켜고 그대로 이동**을 고르면 이동을 예약하고, DeepSeek Harness를 ⌘Q로 완전히 끈 뒤 다시 열 때 **같은 세션 id로** 자동으로 옮겨집니다. 복사본은 만들지 않아요.

**끌어서 옮기기**: 왼쪽 목록에서 대화 줄을 잡아 다른 작업공간의 이름 줄(또는 그 안의 대화 줄) 위에 놓아도 돼요. 옮길 작업공간 줄에 파란 테두리가 보이면 놓으면 됩니다. 같은 작업공간 안에서 끌면 원래처럼 순서만 바뀌어요.

### 이동 방식

| 방식 | 언제 | 세션 id | 원본 | 재시작 |
|---|---|---|---|---|
| **바로 이동** | 닫힌 대화, 로그 16MiB 이하 | 유지 | 지움 | 없음 |
| **다시 켜고 그대로 이동** | 열린 대화, 로그 16MiB 이하 | **유지** | 지움 | 한 번(예약 후 자동) |

- **바로 이동**: `옮기기` 한 번. 로그를 한 번 읽어 새로 쓰고 원본을 지웁니다.
- **다시 켜고 그대로 이동**: 확인 창에서 누르면 이동을 예약합니다. 사이드바의 그 대화 줄에 **`→ Dev`처럼 대상 작업공간 배지**가 붙고, 앱을 완전히 껐다 켤 때 시작하면서 같은 세션 id로 옮깁니다. 옮긴 뒤에는 “이동을 마쳤어요” 알림이 떠서 결과를 알 수 있어요. 복사본은 생기지 않아요.
- 로그를 한 번 다시 쓰는 시간은 1~3MB에서 보통 1초 안입니다.
- 16MiB보다 큰 대화는 메모리 때문에 바로 옮길 수 없어요. `maxArtifactBytes`를 늘리면 가능하지만 메모리를 더 씁니다.

### 세션 삭제

`…` 메뉴 맨 아래의 **세션 삭제** 로 세션을 완전히 지울 수 있어요.

- 기록이 **휴지통**으로 이동하고 사이드바 목록에서 사라집니다.
- 세션 보관과 달리 앱 안에 **되돌리기 버튼은 없습니다.** 필요하면 휴지통에서 파일을 꺼낼 수 있어요.
- 지금 열려 있는 대화를 지우면 목록에서는 **바로 숨고**(보관 처리), 열려 있는 화면은 **앱을 다시 켤 때** 사라집니다.
- 삭제한 대화의 **예약 이동**도 함께 지워집니다.

## 지금은 옮길 수 없는 것

| 경우 | 이유와 할 일 |
|---|---|
| 지금 열려 있는 대화 | **다시 켜고 그대로 이동**을 예약하고 앱을 한 번 완전히 껐다 켭니다. 같은 세션 id로 옮겨집니다. |
| 하위 에이전트 대화 | 부모 대화에 묶인 세션이라 옮기지 않아요. |
| 대상 폴더가 사라진 작업공간 | 폴더를 되살리거나, 작업공간을 지우고 새로 만든 뒤 옮깁니다. |
| 아주 큰 대화 | 기본 16MiB(압축 파일 기준)까지 옮겨요. `maxArtifactBytes`로 늘릴 수 있지만 메모리를 더 씁니다. |
| 다른 DSH 창이 쓰고 있는 대화 | 그 창을 닫은 뒤 다시 시도합니다. |

## 안전장치

- 옮기기 전에 세션 폴더를 `~/.dsh/dsh-workspace-move/backups/`에 복사해 둡니다(최근 5개).
- 바꾸는 순서를 `journal.json`에 먼저 적습니다. 도중에 앱이 꺼져도 다음 시작 때 이어서 마무리하거나 원래 자리로 되돌립니다.
- 새 로그를 다 쓴 뒤 첫 이벤트·마지막 이벤트·이벤트 수를 다시 읽어 확인하고, 그다음에야 작업공간 목록을 바꾸고 원본을 지웁니다.
- 어느 단계에서든 실패하면 원본을 되돌리고 작업공간 목록도 원래대로 맞춥니다. 되돌리기까지 실패하면 아무것도 지우지 않고 이유를 보여 줍니다.
- 작업공간 목록은 `~/.dsh/storages/workspace.json`을 손으로 고치지 않고, DSH의 작업공간 서비스(`detachSession` → `attachSession`)로 바꿉니다.

## 알아 둘 점

- 대화 기록 안에 적힌 예전 파일 경로, Forge 워크트리, 예약 작업은 세션 id로만 이어져요. 파일이 새 폴더로 복사되지는 않습니다.
- 대화 중간에 작업 폴더를 바꾼 기록이 있으면, 옮길 때 마지막 `working-directory/change`를 대상 경로로 다시 남겨 폴더가 어긋나지 않게 해요.
- DSH 업데이트로 세션 헤더나 작업공간 규칙이 바뀌면 플러그인을 다시 확인해야 해요. [docs/upstream-request.md](docs/upstream-request.md)에 정식 기능 제안 초안을 두었습니다.
- 한 번에 한 세션만 옮깁니다. 여러 개를 고르는 기능은 없어요.

## 설치

키트를 받은 폴더에서:

```sh
./install.sh
```

또는 DSH 화면 → **Plugins** → **Add plugin**에 이 폴더의 절대 경로를 넣습니다(예: `/Users/<사용자>/dsh-korean/plugins/workspace-move`). `~/`로 시작하는 경로는 받지 않아요.

설치 뒤 DSH를 다시 켜면 세션 메뉴에 항목이 생깁니다.

## 끄기·지우기

- 잠시 끄기: DSH 플러그인 화면에서 이 카드를 끕니다. 이미 옮긴 대화는 그대로 남아요.
- 지우기: `./install.sh --remove` 또는 플러그인 화면에서 **Remove**.
- 이미 옮긴 대화는 플러그인을 지워도 정상입니다. 옮길 때 만든 상태가 DSH의 정식 상태와 같기 때문이에요.

## 데이터 폴더

`~/.dsh/dsh-workspace-move/` (또는 `$DSH_HOME/dsh-workspace-move/`)

| 파일 | 무엇 |
|---|---|
| `journal.json` | 진행 중인 이동 기록. 정상이면 비어 있어요. |
| `pending.json` | "다시 켜고 그대로 이동" 예약. 다음 시작 때 처리되고 비워져요. |
| `completed.json` | 시작할 때 끝난 예약 이동 기록. 앱이 열리면 알림으로 보여 주고 지워요. |
| `quarantine/` | 새 로그를 만드는 동안 원본을 잠시 두는 곳. 정상이면 비어 있어요. |
| `backups/` | 옮기기 전 세션 폴더 사본(최근 5개). |

`journal.json`이 남아 있고 대화가 목록에 안 보이면, 앱을 한 번 다시 켜 보세요. 그래도 안 되면 `journal.json`과 `backups/`를 지우지 말고 보관한 뒤 알려 주세요.

## 개발

```sh
node scripts/build.mjs   # src/ → lib/client.js
node --test test/*.test.mjs
```

`lib/client.js`는 빌드 결과물이에요. `src/`를 고친 뒤 다시 만들고 함께 커밋합니다.
