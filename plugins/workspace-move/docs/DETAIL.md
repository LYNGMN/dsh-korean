# 작업공간 대화 옮기기

DSH 왼쪽 목록의 대화를 다른 작업공간으로 옮깁니다. 세션 id, 제목, 대화 기록을 그대로 두고, 옮긴 뒤에는 대상 작업공간 폴더에서 이어서 작업합니다.

## 어떻게 쓰나요

1. 옮길 대화의 **…** 메뉴를 엽니다.
2. **작업공간 이동**을 고릅니다.
3. 대상 작업공간을 고르고 **옮기기**를 누릅니다.
4. 결과 화면에서 **닫기**를 누르거나, 잘못 옮겼으면 **되돌리기**를 누릅니다.
5. 지금 보고 있는 대화는 **다시 켜고 그대로 이동**을 예약하고 앱을 한 번 완전히 껐다 켭니다. 같은 세션 id로 옮겨집니다.
6. 왼쪽 목록에서 대화 줄을 다른 작업공간 줄 위로 **끌어다 놓아도** 옮겨집니다. 같은 작업공간 안에서 끌면 순서만 바뀝니다.

## 이동 방식

DSH는 앱이 켜져 있는 동안 열어 둔 대화의 기록 파일을 계속 잡고 있어서, 그 대화를 그 자리에서 옮길 수 없습니다. 확인 창에서 방식을 고릅니다.

| 방식 | 언제 | 세션 id | 원본 | 재시작 |
|---|---|---|---|---|
| 바로 이동 | 닫힌 대화, 16MiB 이하 | 유지 | 지움 | 없음 |
| 다시 켜고 그대로 이동 | 열린 대화, 16MiB 이하 | 유지 | 지움 | 한 번(예약 후 자동) |

- **다시 켜고 그대로 이동**을 누르면 이동이 예약되고, 사이드바 줄에 대상 작업공간 배지가 붙습니다. DeepSeek Harness를 완전히 끄고 다시 열면 시작할 때 같은 세션 id로 옮겨지고, “이동을 마쳤어요” 알림이 뜹니다. 복사본은 만들지 않습니다.
- 16MiB보다 큰 대화는 메모리 때문에 옮길 수 없습니다(설정으로 늘릴 수 있음).

## 무엇이 바뀌나요

- 세션 로그의 헤더에 적힌 작업 폴더(`cwd`)가 대상 작업공간 경로로 바뀝니다.
- 로그 폴더가 대상 작업공간의 프로젝트 폴더로 옮겨집니다.
- 작업공간 목록에서 원래 작업공간의 소유가 풀리고 대상 작업공간 맨 위에 들어갑니다.
- 대화 이벤트는 그대로 복사됩니다. 작업 폴더를 바꾼 기록이 있으면 마지막에 대상 경로를 한 줄 더 남깁니다.

## 안전장치

- 옮기기 전 원본 세션 폴더를 `~/.dsh/dsh-workspace-move/backups/`에 복사합니다(최근 5개).
- 순서를 `journal.json`에 먼저 적고, 새 로그를 만든 뒤 첫·마지막 이벤트와 개수를 다시 읽어 확인합니다.
- 확인이 끝난 뒤에만 작업공간 목록을 바꾸고 원본을 지웁니다.
- 어느 단계든 실패하면 원본과 작업공간 목록을 원래대로 되돌립니다.
- 앱이 도중에 꺼지면 다음 시작 때 저널을 보고 이어서 마무리하거나 되돌립니다.

## 세션 삭제

`…` 메뉴 맨 아래의 **세션 삭제** 로 세션을 완전히 지웁니다.

- 기록은 **휴지통**으로 이동하고 목록에서 사라집니다. 보관과 달리 앱 안에 되돌리기 버튼은 없습니다.
- 지금 열려 있는 대화를 지우면 목록에서는 바로 숨고(보관 처리), 열려 있는 화면은 앱을 다시 켤 때 사라집니다.

## 지금은 안 되는 것

- 지금 열려 있는 대화는 바로 그대로 옮길 수 없습니다. **다시 켜고 그대로 이동**으로 예약한 뒤 앱을 한 번 껐다 켜야 합니다.
- 하위 에이전트 대화는 옮기지 않습니다.
- 대상 작업공간 폴더가 없으면 옮기지 않습니다.
- 기본 16MiB(압축 파일 기준)보다 큰 로그는 거절합니다. 플러그인 설정 `maxArtifactBytes`로 늘릴 수 있습니다.
- 대화 기록 안의 예전 파일 경로, Forge 워크트리, 예약 작업은 세션 id로만 이어집니다. 파일이 새 폴더로 복사되지는 않습니다.
- DSH에 아직 공식 이동 기능이 없어서, 플러그인이 세션 헤더를 다시 쓰는 방식으로 동작합니다. DSH 업데이트 뒤에는 다시 확인해야 합니다.

DeepSeek 공식 플러그인이 아니에요.
