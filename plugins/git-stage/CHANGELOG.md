# 변경 기록

## 1.0.0 (2026-11-15)

첫 공개판입니다.

- 대화 보기 방식(`…` 메뉴)에 "작업 단계" 탭이 생깁니다. 계획 보기 다음 자리에 들어갑니다.
- 세션 작업 폴더의 Git 상태를 읽어 작업실·고치고 저장·검증·공유·합치기·배포 여섯 단계를 끝남·지금·남음·기록 없음으로 칠합니다. 공유·합치기·배포가 지금 단계면 "승인 필요"를 붙입니다.
- 탭 맨 위 "지금" 카드에 지금 단계의 에이전트가 하는 일·상태·올라가는 것·다음 할 일·요청 문장이 한곳에 모입니다. 승인 차례면 테두리와 "승인 필요" 배지, 에이전트가 일하는 중이면 "에이전트 작업 중" 배지가 붙고, 그동안 작업실·저장·검증 단계의 다음 할 일은 "기다렸다가, 끝나면 …"으로 바뀝니다.
- 단계를 누르면 쉬운 뜻과 그 단계의 상태(브랜치·저장 안 된 변경·앞선 커밋·PR·태그)가 펼쳐집니다. 화살표·Home·End 키로 단계를 옮깁니다.
- 바닥 줄에 "14:17에 읽음 · 10초마다 다시 읽어요 · 보기 전용"과 "지금 다시 읽기" 단추가 있습니다.
- 할 일 목록의 진행 중 항목을 "에이전트가 하는 일"로 씁니다.
- 검증 단계는 세션이 실제로 돌린 테스트·빌드 명령(`npm test`, `node --test`, `pytest` 등, `&&`로 이은 마지막 조각이고 파이프가 없을 때)이 이 저장소에서 통과했는지로 봅니다. "14:02 npm test 통과 · 그 뒤로 고친 파일 없음"처럼 보이고, 통과 뒤에 에이전트가 이 저장소 파일을 고쳤으면 다시 돌리라고 합니다. 실행 기록이 없을 때만 할 일 목록의 완료된 검증 항목을 씁니다.
- 열린 PR의 검사(통과·실패·진행 중)와 검토 상태(승인됨·고칠 점 요청됨·검토 기다림)를 한 줄로 보여 줍니다. 검사가 실패하면 합치기 단계에 "검사 실패" 배지와 실패한 검사 이름(최대 3개)을 띄우고, 원인을 찾아 고쳐 달라는 요청을 권합니다.
- 배포 단계는 저장소 맨 위 파일로 배포 방식(Wrangler 설정·`npm run deploy` 스크립트·태그)을 알아보고 그 방식에 맞춰 말합니다. Wrangler·스크립트 배포는 기록이 Git에 남지 않으므로 "배포 기록은 여기서 확인하지 못해요"를 함께 보입니다.
- 공유·합치기 단계에 승인 전에 볼 "이번에 올라가는 것"(저장 기록 제목, 바뀐 파일·줄 수)과 올라가지 않는 저장 안 된 변경을 보여 줍니다.
- 지금 단계에 "이렇게 요청해 보세요" 문장과 "입력창에 넣기" 단추가 붙습니다. 입력창에 넣기만 하고 보내지 않습니다. 문장은 다음 몇 걸음을 묶습니다(예: 공유 단계는 "테스트와 빌드를 돌리고, 통과하면 푸시해서 검토 요청(PR)을 초안으로 열어 주세요. PR 본문에는 바뀌는 것·확인한 것·확인하지 못한 것을 적어 주세요.").
- 채팅 머리 오른쪽에 단계 칩(점 여섯 개 + 지금 단계)이 붙습니다. 승인 차례면 "승인" 글자 배지가 붙습니다. 누르면 저장소 줄·지금 카드·단계 목록 창이 열리고 초점이 창으로 옮겨 갑니다. 창 안 단추는 Tab으로 옮기고, 끝을 넘기거나 Esc·바깥 누르기로 닫습니다.
- Git은 읽기만 합니다. `git fetch`·`push`를 돌리지 않고, `gh`는 묻지 않게 5초 제한·30초 캐시로 부릅니다. 로그인이 만료되면 공유 단계에 "GitHub 로그인 필요"를 띄웁니다.
- 여러 저장소를 담은 폴더(예: `~/Dev`)에서 연 세션은 그 세션이 명령을 돌린 저장소(작업본 포함)를, 찾지 못하면 가장 최근에 Git 활동이 있던 저장소를 따라가고 이유를 한 줄로 밝힙니다. 폴더·브랜치 옆 "저장소" 상자로 하나를 고정할 수 있고, 세션마다 기억합니다.
- 원본 브랜치(`main`)에 있을 때는 작업실 뒤 단계를 모두 "남음"으로 보입니다.
- 플러그인 카드: 브랜치 아이콘(Lucide `git-branch`, DSH 파란색)과 한국어 제목·설명("작업 단계").
