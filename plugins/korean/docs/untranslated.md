# 한국어로 바뀌지 않는 문구

언어팩은 DSH의 화면 사전과 내장 플러그인 카드의 이름·설명을 바꿉니다. 아래 문구는 그 밖에 있어서 한국어 화면에서도 영어로 보입니다.

## 구조상 바꿀 수 없는 곳

| 곳 | 이유 |
|---|---|
| macOS 메뉴 막대, 트레이 메뉴, 업데이트 창, 처음 실행 환영 창 | 앱의 메인 프로세스 사전(약 189키)을 쓰며, 플러그인이 언어를 추가할 수 없습니다. 원문은 `source/<버전>/main-en.json`에 참고용으로 뽑아 둡니다. 한국어 번역은 `desktop/ko.json`에 준비해 두었고, DSH 본체에 한국어를 제안할 때 씁니다. |
| 서버(Host)가 보내는 오류 원문, 도구 설명 | 화면 사전을 거치지 않고 영어 문장이 그대로 옵니다. |
| 식별자로 보이는 내부 모듈 이름(`ui-chat`, `agent-loop` 등, 설정의 플러그인 목록) | 영어 화면에서도 패키지 이름 조각 그대로 보이는 항목입니다. 옮길 영어 문구가 없어 그대로 둡니다. |
| 다른 사람이 만든 플러그인의 카드와 화면 | 카드 이름·설명은 그 플러그인의 `locale/ko.json`에, 화면 문구는 그 플러그인이 등록하는 `ko` 사전에 있어야 합니다. |
| 플러그인 세부 정보의 긴 설명 문서 | 패키지에 든 Markdown 문서를 서버가 골라 보냅니다. |
| 플러그인 둘러보기(인덱스)에서 받아 온 이름과 설명 | 인덱스를 낸 쪽이 한국어를 넣어야 합니다. |
| 터미널의 `dsh` 명령 출력 | 화면 사전을 쓰지 않습니다. |

이 문구들을 한국어로 보려면 DSH 본체나 해당 플러그인에 한국어가 들어가야 합니다.

## 내장 플러그인 카드는 어떻게 바꾸나

플러그인 카드의 이름·설명은 화면 사전이 아니라 패키지마다 딸린 언어 표(`locale/<언어>.json`)에서 옵니다. 앱에 내장된 패키지에는 한국어 표가 없고 앱 파일은 고치지 않으므로, 언어팩이 언어 서비스의 `resolveText`를 감싸서 화면 언어가 한국어이고 표에 한국어가 없을 때 영어 원문으로 번역을 찾아 돌려줍니다. 번역은 `packages/ko.json`에 있습니다.

- 앱 버전이 바뀌어 영어 원문이 달라진 카드는 다시 추출해 번역할 때까지 영어로 보입니다.
- 앱이 이 함수를 바꾸지 못하게 막으면 카드만 영어로 남고, 개발자 도구 콘솔에 `[dsh-korean]` 경고가 남습니다. 나머지 화면 번역은 그대로 동작합니다.
