# 번역 문체 기준

DeepSeek Harness 화면 문구를 한국어로 옮길 때 지키는 기준입니다. 용어는 `glossary.json`을 따릅니다.

## 말투

- 문장으로 끝나는 안내·오류·설명은 해요체로 씁니다. 예: "저장하지 못했어요. 다시 시도해 주세요."
- 버튼·메뉴·탭·제목·표 머리글은 명사형으로 씁니다. 예: "저장", "다시 시도", "세션 삭제".
- 진행 중인 상태는 "~하는 중…", 끝난 상태를 알리는 짧은 표시는 "~됨"으로 씁니다. 예: "저장하는 중…", "복사됨".
- 사용자를 "당신", "귀하"로 부르지 않습니다. 주어를 빼거나 문장을 바꿉니다.

## 오류 문구

- 무슨 일이 있었는지 먼저, 할 수 있는 일을 다음에 적습니다.
- "~에 실패했습니다" 대신 "~하지 못했어요"를 씁니다.
- 원문에 없는 원인이나 해결 방법을 지어내지 않습니다.

## 지킬 것

- `{name}` 같은 플레이스홀더는 이름을 그대로 둡니다. 순서는 한국어 어순에 맞게 바꿔도 됩니다.
- 플레이스홀더 뒤에 조사를 바로 붙여야 하면 문장을 바꿔 "을(를)" 같은 표기를 피합니다. 예: "{name} 삭제" / "{name} 파일을 열 수 없어요".
- 슬래시 명령, 도구 이름, API 필드 이름, 파일 경로, 예시 URL은 원문 그대로 둡니다.
- 제품·기능 이름(`glossary.json`의 `keep`)은 영어로 둡니다.
- 마크다운 문법(`###`, `>`, 목록 기호, 줄바꿈)은 원문 구조를 유지합니다.
- 원문의 범위·조건·가능성("일부", "최대", "~할 수 있음")을 빼거나 단정으로 바꾸지 않습니다.

## 피할 것

- 줄표(`—`, `–`). 쉼표·쌍점·괄호를 쓰거나 문장을 나눕니다.
- 번역투: "~에 대한", "~을 통해", "~되어집니다", "~하시기 바랍니다".
- 영어식 직역 부사: "성공적으로", "조용히", "우아하게".
- 같은 원문을 화면마다 다르게 옮기는 것. 같은 원문은 같은 번역으로 맞춥니다.
- 좁은 버튼에서 두 줄이 되는 긴 이름. 이름은 줄입니다.

## 문장부호와 표기

- 말줄임표는 원문과 같은 `…` 한 글자를 씁니다.
- 숫자와 단위는 원문 표기를 따릅니다(`{count}개`, `{percent}%`).
- 복수형 키(`.one`, `.other`)는 한국어에서 뜻이 같으므로 같은 문장을 씁니다.
- 외래어는 국립국어원 표기를 따릅니다(워크플로, 디렉터리 대신 폴더, 브라우저).
