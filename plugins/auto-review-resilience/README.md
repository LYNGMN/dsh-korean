# 자동 검토 복구

DSH Auto review(도구 자동 검토)가 **레이트 리밋이나 일시 오류로 실패해 도구 본문이 실행되지 않는 문제**를 줄이는 플러그인입니다. DeepSeek 공식 플러그인이 아닙니다.

## 하는 일

Auto review는 도구를 실행하기 전에 같은 모델·같은 계정으로 검토 요청을 한 번 더 보냅니다. 이 요청이 `429 account_rate`나 5xx로 끝나면 Auto review는 재시도 없이 `AUTO_REVIEW_FAILED`로 도구를 막습니다. 본 모델 요청은 DSH의 재시도기가 살리지만, 검토 요청은 그 재시도망 밖에 있습니다.

이 플러그인은 검토 요청만 골라 두 가지를 합니다.

1. **재시도** — `RATE_LIMIT`·`SERVER`·`TIMEOUT`·`TRANSPORT`·`EMPTY_RESPONSE`와 HTTP 429·5xx를 만나면 검토 스트림을 버퍼에 모았다가 같은 provider/model로 다시 보냅니다. 간격은 500ms에서 시작해 두 배씩 늘고(최대 8초), jitter를 더합니다. 검토 출력은 화면에 토큰 단위로 보이지 않으므로 중간 출력이 섞이지 않습니다.
2. **직접 승인 폴백** — 재시도를 다 써도 실패하면 `AUTO_REVIEW_FAILED` 거부를 `ask`로 바꿉니다. 승인 창에서 사람이 허락해야 도구가 실행됩니다. **자동 승인은 하지 않습니다.** 승인자가 없는 헤드리스 실행에서는 실패로 닫힙니다.

실제 검토 거부(`AUTO_REVIEW_DENIED`)는 건드리지 않습니다. 일반 대화 요청과 다른 스트림도 그대로 통과합니다.

## 설치

DSH 플러그인 화면의 **플러그인 추가**에서 이 폴더의 절대 경로를 넣습니다.

```text
<키트 폴더>/plugins/auto-review-resilience
```

`~/`로 시작하는 경로는 DSH가 받지 않으므로 절대 경로로 넣습니다. 키트 전체를 설치할 때는 저장소 루트에서 `./install.sh`를 실행합니다. 프로필 파일을 손으로 고치지 않습니다.

## 설정

기본값으로 바로 동작합니다. 값은 이 번들의 `cordis.patch.yml`에 있습니다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `enabled` | `true` | `false`면 플러그인이 아무 것도 하지 않습니다. |
| `maxRetries` | `3` | 첫 시도 뒤에 더 해 볼 횟수(0~10). |
| `initialDelayMs` | `500` | 첫 재시도 간격(ms). |
| `maxDelayMs` | `8000` | 재시도 간격 상한(ms). |
| `jitterRatio` | `0.2` | 간격에 더하는 무작위 비율(0~1). |
| `askOnFailure` | `true` | 재시도 소진 시 직접 승인을 묻습니다. |
| `fallback` | 없음 | 선택. `{ provider, model }`을 넣으면 지정한 시도부터 다른 모델로 검토합니다. |
| `fallbackAfter` | `2` | 몇 번째 재시도부터 fallback을 쓸지. |

`fallback`을 켜면 검토 입력(세션의 도구 호출 이력)이 그 provider로 전송됩니다. 데이터·비용을 확인한 뒤 켜세요.

## 확인

1. DSH를 다시 열고 플러그인 화면에 **자동 검토 복구** 카드가 보이는지 봅니다.
2. Auto 세션에서 `bash`나 `edit`을 실행합니다.
3. 429가 나면 도구가 바로 막히지 않고, 재시도 뒤 실행되거나 직접 승인 창이 뜹니다.
4. 플러그인을 끄면 DSH 기본 동작(검토 실패 시 즉시 차단)으로 돌아갑니다.

## 한계

- 계정의 레이트 리밋 자체를 없애지는 않습니다. 재시도와 승인 폴백으로 **도구가 막히는 일**을 줄입니다.
- 검토 모델을 기본으로 바꾸지 않습니다. 바꾸려면 `fallback`을 켜야 합니다.
- Auto review가 꺼진 세션에는 영향이 없습니다.
- 승인 폴백을 쓰면 그 호출은 자동 검토 없이 실행됩니다. 사람이 직접 승인하는 것이므로 `workspace-write` 모드의 승인과 같은 수준입니다.
